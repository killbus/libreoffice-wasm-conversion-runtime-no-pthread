## Static artifact evidence

Independent inspection of the downloaded artifact reports an unshared memory,
no pthread-specific imports, no pthread worker bootstrap, and no worker
sidecar. `wasm-objdump` reports an initial memory of 16,384 pages and a maximum
of 65,536 pages without the shared-memory flag. The conversion failure is
therefore a single-threaded runtime deadlock rather than accidental publication
of threaded bytes.

## Runtime evidence

A direct Node invocation initialized in approximately 817 ms. During the first
`convert()` call it then consumed one CPU core continuously. A 45-second V8
sample attributed nearly all samples to this stable chain:

```text
wasm-function[203812]
  -> wasm-function[22202]
  -> wasm-function[81351]
  -> wasm-function[23516]
  -> wasm-function[23329]
  -> wasm-function[23328]
  -> wasm-function[23363]
```

`wasm-function[22202]` matches the pinned
`sal/osl/unx/conditn.cxx::osl_waitCondition()` implementation, including the
condition state at object offset 72 and the null-timeout polling path. Replacing
its first instruction with a diagnostic trap in a copy of the artifact caused
the first conversion to trap immediately. The original archive and runtime
were not modified.

## Root cause

`wasm-function[81351]` contains a guarded, function-local static
`osl::Condition`, followed by `osl_waitCondition(..., nullptr)`. The pinned
LibreOffice tree has exactly one function-local static `osl::Condition`:
`getInitCondition()` in `toolkit/source/awt/vclxtoolkit.cxx`. Its sole wait is
in `VCLXToolkit::VCLXToolkit()` immediately after `CreateMainLoopThread()`.

LibreOfficeKit's Emscripten unipoll path already calls `InitVCL()` synchronously
on the owning JavaScript worker. Consequently `Application::IsInMain()` remains
false because no `Application::Main()` loop is entered, even though VCL is
initialized. Constructing `VCLXToolkit` therefore tries to create a redundant
VCL main-loop thread and waits for `ToolkitWorkerFunction()` to signal the
condition. In the no-pthread profile that nested thread cannot execute, so the
condition can never be set.

## Correction prepared for the fourth build

The patch ports the current upstream guard to the pinned LibreOffice tree:
`VCLXToolkit::VCLXToolkit()` starts and waits for a toolkit main-loop thread only
when `comphelper::LibreOfficeKit::isActive()` is false. This is intentionally
narrower than changing the condition implementation or globally weakening
waits. The LibreOfficeKit unipoll path has already completed the VCL
initialization that the worker would check, and the worker would otherwise only
set the condition and return when `IsVCLInit()` is true. Upstream `master` at
commit `8ce6cb1318efd10d9912a0d4f8dccb9b54dc8bb9` contains the same guard.
