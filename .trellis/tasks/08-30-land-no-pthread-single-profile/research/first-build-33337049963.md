# First native build diagnosis

## Build identity

- GitHub Actions run: `33337049963`
- Job: `99325717569`
- Source commit: `6a55ea6b9e646b296745c7c2353931f476c3fbdf`
- Result: failed in `Build LibreOffice WASM` after 1 hour 56 minutes

## Failure

The final `soffice.html` link emitted the Emscripten warning that `-pthread`
was combined with `ALLOW_MEMORY_GROWTH`, then failed with:

```text
wasm-ld: error: --shared-memory is disallowed by sfnt.o because it was not
compiled with 'atomics' or 'bulk-memory' features.
```

No native artifact was produced. The upload step therefore correctly reported
that no `wasm/soffice.*` files were available.

## Root cause

`EMSCRIPTEN_INTEL_GCC.mk` includes `unxgcc.mk`. The generic Unix platform file
sets `gb_CXX_LINKFLAGS := -pthread` when libc++ is present and immediately
expands that value into `gb_CXXFLAGS`. The first no-pthread patch removed the
explicit Emscripten pthread flags but did not remove this inherited compile and
link flag, producing a mixed build: ordinary objects were non-atomic while the
final C++ link still requested shared memory.

## Correction

The no-pthread patch now filters `-pthread` from the already-expanded
`gb_CXXFLAGS` and clears `gb_CXX_LINKFLAGS` immediately after including
`unxgcc.mk`. `build/build-wasm.sh` also checks these exact invariants and rejects
active Emscripten pthread settings before configuration or compilation.
